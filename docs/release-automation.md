# Release automation

fastlane is the release substrate (ADR-0002). `make` is the interface; every
release verb delegates 1:1 to a lane. Nothing here needs a bespoke script.

| Make target | Lane | Runs on |
|---|---|---|
| `make asc-bootstrap` | `bootstrap_asc` | Linux or macOS |
| `make asc-status` | `status` | Linux or macOS |
| `make testflight` | `beta` | macOS only |
| `make screenshots` | `screenshots` | macOS only |
| `make metadata-push` | `metadata` | Linux or macOS |
| `make release` | `release` | Linux or macOS |
| `make notarize-mac` | `notarize` | macOS only |
| — | `mac_beta`, `certs` | macOS only |

The macOS-only lanes call `require_macos` and stop immediately elsewhere. gym
does not fail closed on its own, so without that guard a Linux run dies twenty
steps later with a confusing "Project file not found".

## 1. One-time setup

```bash
brew install rbenv          # macOS system Ruby is too old, always
rbenv install "$(cat .ruby-version)"
bundle install              # installs fastlane 2.237.0 from Gemfile.lock
bundle exec fastlane lanes  # sanity check
```

`Gemfile.lock` is committed and carries `arm64-darwin`, `x86_64-darwin` and
`x86_64-linux`, so the same lock resolves on Apple silicon, Intel and CI. It
was generated by Bundler 4.x; a machine with an older bundler will fetch that
version once, automatically, before installing.

There is no `Pluginfile`. Every lane uses core actions only — if you ever run
`fastlane add_plugin`, re-add the `eval_gemfile` lines documented in `Gemfile`
and write an ADR saying why.

## 2. The App Store Connect API key

Create it in App Store Connect → Users and Access → Integrations → App Store
Connect API. **It must be a Team key with the App Manager (or Admin) role.**
Individual keys cannot touch the provisioning endpoints or notarytool, so they
break `bootstrap_asc`, `certs` and `notarize`.

You get a `.p8` file exactly once. Three values matter: the file, the 10-char
Key ID, the issuer UUID.

Store the key in 1Password and reference it from `.env` — never paste it into
a file in the repo:

```bash
# .env  (gitignored)
APP_STORE_CONNECT_API_KEY=op://agentic/asc-api-key/base64_p8
APP_STORE_CONNECT_API_KEY_ID=op://agentic/asc-api-key/key_id
APP_STORE_CONNECT_API_ISSUER=op://agentic/asc-api-key/issuer_id

# then run lanes through op, which resolves the op:// refs at exec time
op run --env-file=.env -- bundle exec fastlane beta
```

Base64 (`base64 -i AuthKey_ABC123.p8 | tr -d '\n'`) is the CI-friendly form
and is what the lanes expect by default. The alternative,
`APP_STORE_CONNECT_API_KEY_P8_PATH`, points at a `.p8` on disk — handy
locally, useless on an ephemeral runner. Set exactly one; the Fastfile errors
if both or neither are present.

`.gitignore` already blocks `*.p8`, `*.p12` and `*.mobileprovision`, and
`.claude/settings.json` denies agent reads of all of them.

In CI, the same three names become repository secrets. See
`.github/workflows/release.yml` (installed when `ops.ci_system:
github_actions`) for the exact wiring.

## 3. Lane walkthrough

**`bootstrap_asc`** — registers every bundle ID in `contracts.md` §2 and
enables its capabilities, then verifies the parts Apple will not let it
create. Run it once per app, and again after enabling a component.

```bash
make asc-bootstrap                              # do it
bundle exec fastlane bootstrap_asc dry_run:true # show the plan first
```

It derives the ID list from the directories present in the repo, so a pruned
app never registers identifiers it does not ship. What it cannot do — create
the app record, create the App Group, create an iCloud container — it fails on
loudly, pointing at `docs/asc-setup.md`. That is Apple's limit, not fastlane's:
the public API has no create-app endpoint, and `produce` authenticates only
with an Apple ID + 2FA session.

**`status`** — the same registry, read-only, plus app record, versions
(live / edit / in review / pending), recent builds with processing state,
TestFlight groups, and the three build numbers (`git rev-list --count HEAD`,
TestFlight latest, App Store live) side by side so divergence is visible
before an upload rejects.

**`beta`** — icon preflight → export-options assertion → `gym` → `pilot`.
One pilot call uploads, waits for processing, and distributes.

```bash
make testflight
bundle exec fastlane beta external:true groups:'Friends & Family'
bundle exec fastlane beta changelog:'Fixes the widget refresh'
```

Internal testers get the build with no review. External distribution needs
`groups:` and triggers beta review. Never set `PILOT_DISTRIBUTE_EXTERNAL` in
`.env` — `distribute_external` and `submit_beta_review` share that one
environment variable with opposite defaults, so setting it silently changes a
behaviour you did not mean to change.

**`metadata`** — pushes text and screenshots, no binary. Runs twice when the
`mac` component is on: once `platform: "ios"`, once `platform: "osx"` against
the same app record (Universal Purchase).

**`release`** — `precheck` at `:error` level as a fail-fast gate, then submits
for review with phased release on and automatic release off. Nothing uploads
if the copy would bounce.

**`certs`** — see §6. Refuses to run unless `MATCH_GIT_URL` is set.

**`mac_beta` / `notarize`** — Mac App Store TestFlight, and Developer ID +
notarytool for direct distribution. Both refuse when the `mac` component is
absent.

## 4. Metadata as code

`fastlane/metadata/` is the source of truth; App Store Connect is a cache of
it. File names are deliver's API, not a convention — the full schema is
documented at the top of `fastlane/Deliverfile`.

`fastlane/metadata/en-US/release_notes.txt` is deliberately shared: the `beta`
lane reads it as TestFlight's "What to Test" and `metadata`/`release` upload it
as "What's New". One file, one story per version.

Adding a locale is adding a directory. Directory names must match deliver's
language list (`en-US`, `de-DE`, `fr-FR`, …).

Every placeholder file in the tree says PLACEHOLDER out loud. Rewrite them all
before the first submission — `precheck` fails the `release` lane on
placeholder text, "coming soon", other platform names, and unreachable URLs.

## 5. Screenshots

`make screenshots` drives `MyAppUITests` through the `MyAppScreenshots` scheme
on the simulators listed in `fastlane/Snapfile`, then writes
`fastlane/screenshots/<locale>/*.png`.

deliver matches screenshots by **pixel resolution**, never by file or folder
name. The required sets are 1320×2868 (6.9" iPhone) and, if the app ships on
iPad, 2064×2752 (13" iPad). Everything else Apple auto-scales. That is why the
Snapfile captures on iPhone 17 Pro Max rather than the plain iPhone 17 the
Makefile uses for tests: a 6.3" device produces 1206×2622, which lands in an
optional slot and leaves the required one empty.

snapshot is **iOS simulator only**. fastlane has no macOS or watchOS
screenshot automation. Mac screenshots (1280×800, 1440×900, 2560×1600 or
2880×1800) are captured by hand — or by an `XCUIScreen.main.screenshot()`
test you write — and dropped into `fastlane/screenshots-mac/<locale>/`, which
the `metadata` lane picks up automatically when it exists.

`frameit` (device frames around the shots) is off by default because it needs
ImageMagick and community-maintained frame assets that lag new hardware.
Enable per run with `FRAMEIT=1 make screenshots`, or permanently with
`ops.frameit: true` at onboarding.

## 6. Signing: automatic or match

Default is **automatic (cloud) signing**, and for App Store distribution it
genuinely works on an ephemeral runner: Xcode 13+ cloud-managed *distribution*
certificates keep the private key with Apple. The lanes thread
`-allowProvisioningUpdates` plus the API key through gym's `xcargs` and
`export_xcargs` (gym has no native flag for it), materialising the base64 key
to a temporary `.p8` because `-authenticationKeyPath` needs a real file.

Switch to **match** when any of these is true:

- You ship a Developer ID / notarised Mac build. Developer ID certificates are
  *not* cloud-managed — this is the strongest reason.
- More than one human or machine signs the app.
- You want signing state reviewable and revocable in one private repo.

Turning it on: create a private certs repo, set `MATCH_GIT_URL` and
`MATCH_PASSWORD`, run `bundle exec fastlane certs readonly:false` once on a
Mac, and set `ops.signing: match` so the docs agree. CI stays read-only —
`certs` defaults `readonly` to `is_ci`, and `setup_ci` (which creates the
temporary keychain, so you never hand-roll `security create-keychain`) forces
it anyway. **CI must never mint certificates.**

`ExportOptions.plist` is committed for the manual
`xcodebuild -exportArchive` path. gym regenerates its own copy every run, so
the two could drift — `assert_export_options` fails the lane if they disagree.
It must use the legacy method spellings (`app-store`, `developer-id`): gym's
whitelist rejects Xcode 15's `app-store-connect` and `release-testing`.

## 7. Coexisting with Xcode Cloud

Both are supported and they do not conflict. Xcode Cloud runs
`ci_scripts/ci_post_clone.sh` on Apple's runners and needs no API key;
archive and TestFlight distribution are native Xcode Cloud actions. fastlane
and Xcode Cloud are disjoint consumers of the same `Config/Versions.xcconfig`
write step (ADR-0007).

One rule: **pick one archiver per tag.** If Xcode Cloud archives a commit and
the `beta` lane also archives it, build numbers double-increment and App Store
Connect gets two builds claiming the same version.
